## Submission deadline

- Deliverables due: 9 August 2026.
- Submit by email to `outreachsg@garena.com` with one Google Drive folder named for the team.
- Do not modify deliverables after submission.

## Required deliverables

### 1. Slide deck proposal

- PDF with no more than 15 slides.
- Must include the problem, target user, solution, AI contribution, expected impact, technical decisions, and implementation details.

### 2. Working end-to-end prototype source

- Must demonstrate the complete core experience or workflow and expected features.
- Must show user interaction, AI contribution, and the outcome created.
- Workflow proof should include the initial trigger, key steps, models or agents, tools or APIs, human review, exception handling, and final output or action.
- Static mock-ups are insufficient; production readiness is not required.
- Repository must contain complete source, setup instructions, architecture, prompts or agent configuration, and third-party disclosure.
- No passwords, API keys, or confidential credentials.

### 3. Demo video

- Maximum five minutes.
- Must demonstrate the complete core experience or workflow and expected features of the working prototype.

## Judging traceability

| Criterion | Weight | Afterplay proof | Authoritative evidence before submission |
| --- | ---: | --- | --- |
| Problem-solution fit | 40% | Small streamers can receive reach without building a returning audience; Afterplay reduces uncertainty by running evidence-backed growth experiments. | Product contract, user evidence in deck, judge-understandability test, demo opening. |
| Build quality | 30% | One experiment works from diagnosis through approval, simulated distribution, measured result, learning, and next experiment. | Browser test, service tests, adapter tests, full live demo rehearsal, build and accessibility checks. |
| Originality | 30% | Persistent creator memory and coordinated specialist agents choose and learn from experiments; editing is one execution arm. | AI contract, explainable hypothesis screen, removal test, competitor boundary in deck. |

## Workflow proof matrix

| Brief requirement | Product moment | Required implementation evidence |
| --- | --- | --- |
| Initial trigger or input | Seeded creator baseline and completed observation window | Workspace and baseline load from the public service. |
| Models or agents | Strategist, Scout, Producer, Analyst | Team activity with structured outputs and shared evidence. |
| Tools or APIs | Strategy director, media records, simulated distribution adapter | Disclosed runtime mode and adapter receipts. |
| Human review | Creator inspects and approves current experiment output | Stale and unapproved actions fail closed. |
| Exception handling | Live AI failure, stale revision, rejected work, adapter failure | Visible error state and public service response. |
| Final output or action | Approved sample publication, performance learning, next experiment | Receipt, result ingestion, learning, and next hypothesis in the UI. |
